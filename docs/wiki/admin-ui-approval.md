# Scenario: Admin UI approval

Use this scenario when an approver should review requests in a browser. The UI
is served by Lucifer Gate; no separate frontend service is required.

## 1. Obtain the admin secret

Run initialization before starting the server:

```bash
npx lucifer-gate --init .
```

Save the printed `luc_admin_...` credential securely. Lucifer stores only its
hash and salt in `lucifer.json`; the original secret cannot be recovered from
the file.

## 2. Start the web channel

```bash
npx lucifer-gate --config ./config/lucifer.json
```

The web approval channel is enabled when the configuration contains the admin
secret hash and salt generated by `--init`. Open:

```text
http://localhost:3001/admin/approvals
```

Use the configured host and port when the browser is on another machine.

## 3. Review a pending request

Open the page in a browser that can reach the server. It loads pending requests
and receives new requests and decisions over a live server-sent-events stream.
Inspect the command, caller, request ID, and risk warnings before deciding.

## 4. Approve or deny

For an approval, choose:

- **Exact** to cache the complete command.
- **Prefix** to cache the first two command tokens.
- **2 hours**, **8 hours**, or **permanent** for the lifetime.

Choose **Deny** to reject the current request without creating an approval.
The decision is persisted in SQLite and the waiting execute request resolves.

The web API requires the same credential as a bearer token:

| Route | Purpose |
|---|---|
| `GET /api/v1/admin/approvals/pending` | List pending requests |
| `POST /api/v1/admin/approvals/stream-ticket` | Create a one-time SSE ticket |
| `GET /api/v1/admin/approvals/stream?ticket=...` | Receive live updates |
| `POST /api/v1/admin/approvals/:requestId/decide` | Approve or deny a request |

An approve request is shaped like:

```json
{
  "action": "approve",
  "matchType": "exact",
  "duration": "2"
}
```

A denial only needs:

```json
{ "action": "deny" }
```

Send `Authorization: Bearer YOUR_ADMIN_SECRET` for direct API calls. The
browser UI handles the ticket exchange and decision calls for you.

## Security notes

- Protect the UI with TLS and network access controls when it is not local.
- Never put the admin secret in a URL, browser bookmark, shell history, or
  source repository.
- The admin API is bearer-authenticated and rate-limited.
- If Telegram and the Admin UI are both enabled, the first decision wins.
